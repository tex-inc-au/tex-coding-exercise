# Code review exercise (≈15 minutes)

You are reviewing a small React screen that a teammate shipped for **TEX Schools**: a teacher’s class roster with search and an “active only” filter.

## Your task

1. Run the app (`npm install` then `npm run dev` in this folder).
2. Click around: search, toggle **Active students only**, watch the list and the browser console.
3. Talk through what you notice — bugs, risks, missing UX, and what you would change before merge.
4. You do **not** need to fix everything; prioritize what matters most for teachers and student data.

## Context

- Stack: React + TypeScript (same as TEX Schools web).
- Data is mocked locally; there is no real API in this exercise.
- Think aloud: we care as much about *how* you reason as what you find.

## Hints we will not give

There is no checklist. Treat this like a real PR review on production-bound code.
